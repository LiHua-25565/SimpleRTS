SimpleRTS 项目架构与协作指南（v1.4）
1. 项目简介
本游戏是一个 2D 即时战略游戏（类红警/帝国时代），使用 C++ 和 SDL3 构建。目前实现了地图渲染、单位选择、基于流场的群体移动、编队排列和简单的障碍避让。

2. 技术栈与构建
语言：C++17

图形/输入：SDL3（含 SDL_image、SDL_ttf、SDL_mixer）

数学：自实现 Vector2、CollisionBox

构建工具：Visual Studio 2022（解决方案 SimpleRTS.sln）

版本控制：Git，托管于 GitHub

构建前需将 SDL3 开发库路径配置到 VC++ 目录中。

4. 核心概念
4.1 ECS 组件
所有数据继承自 Component，存储在 GameObject 的 unordered_map<type_index, unique_ptr<Component>> 中。
常用组件（components.h）：

Movable：speed, target, flow_target, velocity, move_mode

Renderable：texture, color, layer

Selectable：is_selected

UnitType：category (Melee/Ranged/...)

Structure / Harvestable：标记建筑/资源（用于障碍）

Health：生命值

通过模板方法获取：obj->get_component<Movable>()，返回可修改指针；添加组件用 obj->add_component<T>(args...)。

4.2 地图 (GameMap)
基于格子网格，cell_size = 10 像素，默认 200×200 格。

地形类型（TerrainType）：Mud（可通行）、Water（不可通行）、Wood, Rock, Gold（将来对应资源实体）。

存储：grid[y][x]，提供 is_cell_passable(x,y) 检查。

流场生成：

generate_goal_flow_field(world_goal) → 全图 Dijkstra 距离场 + 方向场。

generate_local_flow_field(world_goal, max_dist_cells) → 限制扩散步数的局部方向场（用于近距离精确导航）。

方向采样：sample_flow_from_box(flow, collision_box) → 按碰撞盒覆盖面积加权平均。

4.3 实体管理 (WorldEntityMgr)
持有所有 GameObject*（unordered_set）和四叉树 QuadTree（基于格子坐标）。

插入/移除时自动更新四叉树。

每帧调用 on_update() 处理脏实体重插入。

区域查询：query_area(area, outVector) 返回与给定 CollisionBox 相交的实体列表。

4.4 移动系统 (MoveSystem)
核心流程 (on_update)：

correct_unwalkable_targets()：将落在水中的 flow_target 修正到最近陆地。

update_global_flow_cache()：按 flow_target 收集活跃目标，为每个新目标生成全图流场（缓存复用）。

update_local_flow_cache()：当单位距离个人目标 < LOCAL_FLOW_RADIUS_CELLS 时，为每个精确目标生成局部流场（缓存复用）。

move_units(delta)：

计算 dist_to_target（到个人偏移点距离），< 5 像素则停止。

调用 get_flow_direction() 获取流场方向（优先局部流场，回退全局）。

结合 compute_wall_repulsion（射线障碍斥力）和 compute_separation（单位间分离力）。

归一化后乘以速度，更新位置。

push_idle_units()：对已停止的单位，仅用分离力和墙壁斥力做微调，允许后来者推挤。

流场方向获取 (get_flow_direction)：

如果 dist_to_target < LOCAL_FLOW_RADIUS_CELLS * cell_size，尝试使用局部流场（键 = vec_to_key(target)）。若局部流场未缓存则调用 GameMap::generate_local_flow_field 生成。

若局部流场返回零向量或不在范围内，回退到全局流场（键 = vec_to_key(flow_target)）。

4.5 渲染管线 (RenderMgr)
begin_frame() → 提交 RenderCmd（通过 push_main_cmd 等）→ end_frame(renderer) 排序绘制。

RenderCmd：支持纹理矩形、纯色矩形、线条（is_line=true）、边框。

渲染层级顺序：Map → Ground → Unit → Building → Projectile → SelectBox → FeedbackLine → UI。

相机变换在 render_main 中统一进行（非 UI 层）。

4.6 输入与场景 (GameScene)
左键点击空地：计算命令中心（cmd_center），调用 compute_formation_targets 按类别排列单位，为每个单位设置 target（精确偏移点）和 flow_target（命令中心），同时添加反馈线。

右键拖拽：移动摄像机。

S 键：停止选中单位。

小地图点击：跳转视角。

5. 当前任务与扩展方向
5.1 立即可做（简单，适合新成员上手）

5.2 中等难度（逻辑类）
建筑物放置

按 B 键进入建造模式，显示半透明预览，点击确认后创建建筑实体（挂载 Structure 组件）。

扣减资源，更新四叉树和流场。

涉及文件：新建 building_placer.h/cpp，扩展 ObjectFactory，修改 GameScene::on_input。

基础战斗系统

添加 Attack 组件，CombatSystem 在 on_update 中检测攻击范围内的敌人、造成伤害、销毁实体。

涉及文件：新建 combat_system.h/cpp，修改 components.h，注册到 GameScene。

5.3 高级（深入核心）
动态障碍更新

当建筑被摧毁或资源被采集后，自动清理对应流场缓存，让移动系统重新寻路。

地形/地图编辑器

实现地图文件的读写（之前讨论过的 JSON + 二进制格式），并提供一个简单的编辑界面。

6. 协作建议
所有新功能请创建独立的分支（如 feature/building-system），通过 Pull Request 合并到 dev 分支。

修改现有核心类（如 move_system）前，先与主程沟通，避免冲突。

新增模块尽量放在独立文件中，保持低耦合。

7. 兵种 / 建筑编辑器（数据驱动）
入口：主菜单「兵种建筑编辑」，或直接按 F2。

7.1 能力
- 内置兵种 / 建筑会直接出现在编辑器里，可编辑但不可删除。
- 新建 / 删除自定义兵种、建筑与科技定义，实时预览名字文字纹理。
- 科技页：设置科技名字、研究时间、木/肉/金/石成本，以及强化效果
  （目标兵种或全部兵种 + 攻击力/攻击距离/生命上限/移动速度 + 数值）。
  研究完成后，已有单位立即生效，新生产的单位也会自动带上效果。
- 兵种可设置：名字、纹理文字（空 = 名字前 4 字，最多 4 字）、生命值、
  普通/穿刺/攻城三种伤害的防御减免、速度、生产时间、木/肉/金/石成本、
  前置科技（从科技表勾选，可多选）、伤害类型（普通/穿刺/攻城）。
- 兵种插件（bitmask，可扩展）：
  * 攻击插件：攻击力、伤害类型、攻击距离、攻击间隔、远程/近战。
  * 采集插件：采集量、采集间隔、携带上限。
- 建筑可设置：名字、纹理文字、生命值、三种伤害的防御减免、占地格数、
  建造时间、成本、建造前置科技（勾选）、资源提交点、可研究科技（勾选）、
  可生产单位（内置 + 自定义）。
- 建筑“可生产单位”里勾选的前置科技会自动补进该建筑的研究列表，避免出现
  “需要科技但没有任何地方能研究”的死锁；研究完成后写入玩家全局科技表，
  单位和建筑的前置科技都按这张表判定。
- 纹理始终由文字生成，使用阵营色渲染，因此不同玩家的单位/建筑仍然可区分。
- 导出 / 导入：defs/<文件名>.srdef（UTF-8、制表符分隔，版本 4 带科技效果；
  旧版本文件仍可载入，旧 armor_value 会转换成三种伤害的减免）。
  启动时自动载入 defs/custom_defs.srdef，仓库自带「剑士 / 长矛兵 / 骑兵 /
  投石车 + 兵营 / 马厩 / 攻城工坊 / 仓库 + 三种科技」示例。

7.2 数据流
- 内置类型 ID 仍是 0..99，自定义类型从 100 开始，直接 cast 进
  UnitEntityType / BuildingEntityType，ECS、生产队列、寻路和地图存档不需要额外分支。
- entity_defs.h/cpp 提供 EntityCatalog（内置默认值 + 定义库 + .srdef 读写）。
- ObjectFactory 按定义创建全部单位/建筑并挂载插件组件；TextureCache 使用
  定义里的 texture_text（空则用名字）生成文字纹理，不读取图片文件。
- 伤害类型规则（ArmorModifier）：
  * 普通：目标对应减免全额生效；
  * 穿刺：只受目标对应减免的 50%（克制高防目标）；
  * 攻城：对建筑伤害 ×1.5 且只受 50% 减免，对非建筑伤害 ×0.75。
- 生产列表由 production_data.cpp 根据定义即时生成；地图编辑器也会自动出现
  “自定义兵种 / 自定义建筑”工具组，可把自定义实体摆进地图并随 .srmap 保存。

7.3 编码
- 本功能新增/修改的源文件统一为 UTF-8 with BOM；MSVC 会优先识别 BOM。
- 仍保留 GBK 的旧文件继续由 CMakeLists 里的 /source-charset:.936 处理。

8. 2v2 地图 map2v2
- 地图文件：maps/map2v2.srmap，尺寸 320×240，4 个基地：
  玩家 1 左上、玩家 2 左下（同盟），玩家 3 右上、玩家 4 右下（同盟）。
- 中央椭圆湖把战场分成上下两条进攻走廊；湖岸树林、基地侧翼大金矿和
  中央资源点提供扩张与争夺目标。
- 在选择界面选中 map2v2 时，默认自动配置成：
  人类 + AI 队友（team 0） vs 两个 AI（team 1），也可以手动改阵营/位置/颜色。
- 2v2 开局每个玩家有 300 木 / 200 肉；每个 AI 也会得到一个起始靶场，
  保证四个玩家都能较快进入交战。
- 新增内容：剑士、长矛兵、骑兵、投石车；兵营、马厩、攻城工坊、仓库；
  步兵训练、骑兵训练、攻城工程。投石车使用攻城伤害，专门拆建筑。
- 生成脚本：gen_map2v2.ps1，可重新生成并验证地图资源布局。

9. UI 操作反馈
- 鼠标在生产/建造/研究按钮上停留约 0.45 秒，会显示按钮说明：
  成本、时间、生命/攻击/防御、前置科技、可生产/可研究内容、科技效果等。
- 点击按钮但资源不足时，屏幕左侧显示红色提示框，列出：
  需要资源、拥有资源、缺少资源，并在 5 秒后自动消失。

10. 新手教程与多模式地图（v1.2，v1.4 扩展）
- 新手教程是独立的 TutorialScene，占位在 scene_mgr 的 Tutorial 场景；
  game_scene 使用独立的 tutorial.srmap 和专用教程面板，不进入普通对局。
- TutorialScene 持有自己的 GameScene 实例；GameScene 的 tutorial UI 通过
  tutorial_external_ui 关闭，由 TutorialScene 绘制教程面板。
- tutorial.srmap：160×120，两个城镇大厅（人类 + 敌方），7 步教程目标。
- v1.4：右上角常驻胜利目标「摧毁敌方城镇大厅」并显示大厅 HP；
  第 6 步生成 3 名敌军弓兵突袭和 3 名玩家弓兵增援；第 7 步要求真正摧毁敌方大厅。
- 多模式地图：
  * 1v1：map1v1_duel / map1v1_river
  * 2v2：map2v2 / map2v2_lake / map2v2_forest
  * 3v3：map3v3_river / map3v3_ring
  * 4v4：map4v4_forest / map4v4_lake
- 地图文件名以 map1v1 / map2v2 / map3v3 / map4v4 开头时，选择界面自动配置
  人类 + AI 队友 vs 对面 AI；旧地图仍然保持手动加 AI 的方式。
- 生成脚本：gen_versus_maps.py；可重新生成并验证 1v1~4v4 对称地图。

11. 地图初始资源（v1.3）
- .srmap 在实体行之后可以写：
  S <player> <wood> <food> <gold> <stone>
- 每个玩家一行；缺省没有 S 行时四项都为 2000。
- 地图编辑器的「初始资源」弹窗按玩家编辑四项数值，保存时自动写入。
- GameScene::setup_match 读取 map_io 返回的 PlayerStartResources，设置每个玩家的
  木/肉/金/石，不再使用写死的 150/300。
- 地图编辑器使用 load_map_resize 载入任意尺寸地图，并支持 2/4/6/8 玩家。


12. 教程胜利目标（v1.4）
- TutorialScene 右上角绘制胜利目标横幅，调用 GameScene::get_tutorial_enemy_tc_hp
  实时显示敌方城镇大厅 HP；敌方大厅在教程中只有 300 HP。
- 第 6 步（索引 5）触发 start_tutorial_wave：敌军弓兵向玩家大厅移动，玩家获得增援；
  清除全部 wave 单位后进入第 7 步。
- 第 7 步（索引 6）检测敌方城镇大厅是否还存在；摧毁后 tutorial_step_ 变为 7，
  教程完成，并明确普通对局胜利条件为「摧毁敌方阵营所有建筑」。
